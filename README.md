# AI Project Manager Assistant

Учебный мультимодальный помощник руководителя корпоративного ИТ-проекта.
Будущий репозиторий: `ai-project-manager-assistant`.
Помогает с ролями, процедурами, ИСУП, отчётностью и рисками.
В RAG использует нормативные документы и указывает названия источников.
При недостатке найденных данных сообщает об этом; положения регламентов не выдумывает.

## Устройство проекта

```text
main.py                 запуск asyncio и Telegram polling
bot.py                  AsyncTeleBot (pyTelegramBotAPI)
config.py               .env, модели, пути и системная роль
handlers/               start/help/stats/index, text/mode, voice, image, document_upload
services/               router, OpenAI, STT, Vision; TTS и генерация — legacy
rag/loader.py           PDF/TXT/MD/DOCX → абзацы → chunks (1000, overlap 200)
rag/index.py            OpenAI embeddings → существующая ChromaDB
rag/query.py            retrieval (top 3) → контекст с источниками → LLM
utils/                  журнал, временные файлы, пользовательские сессии
tests/                 тесты (каталог без начального пробела)
data/documents/         три нормативных DOCX
data/chroma_db/         постоянный локальный индекс
```

DOCX извлекается через python-docx: непустые обычные абзацы в порядке документа.
Таблицы, колонтитулы и изображения из DOCX не извлекаются.
Имя файла сохраняется в `metadata.source` и передаётся LLM.
Память: словарь в RAM по user_id, до 20 сообщений и булево состояние RAG;
после перезапуска очищается. `/reset` очищает историю.
Загрузка документов через Telegram по-прежнему только показывает инструкцию:
файлы нужно поместить в `data/documents/` вручную.

## Запуск в Windows PowerShell

Рекомендуется Python 3.11 или 3.12. Для голосового OGG требуется FFmpeg в PATH.

```powershell
cd C:\Learning\Cursor\PEm09_AI_Project_Manager_Assistant
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env своими ключами
.\.venv\Scripts\python main.py
```

Обязательны `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`.
`USE_PROXYAPI=false` — прямой OpenAI, `true` — ключ ProxyAPI и его endpoint.
Необязательны `BOT_MODE=text`, `DEFAULT_VOICE=alloy`, `LOG_LEVEL=INFO`.
Исходный код по умолчанию использует ProxyAPI, поэтому явно задайте нужное значение.
Поле `DB_PATH` из старого примера не управляет Chroma: индекс хранится в `data/chroma_db/`.
Ключи не коммитьте; корпоративные документы также исключены из Git.

## Telegram

После `/start` появляется постоянная клавиатура:

- `📚 RAG: ВКЛ` / `📚 RAG: ВЫКЛ` — переключает RAG и обновляет подпись кнопки.
- `📊 Статистика` — тот же обработчик, что `/stats` (число фрагментов).
- `🔄 Обновить индекс` — тот же обработчик, что `/index`; перестраивает
  существующую коллекцию и использует API эмбеддингов. Не запускайте параллельно
  с другой индексацией или вопросами; при ошибке исправьте причину и повторите.
- `🧹 Новый диалог` — тот же обработчик, что `/reset`; очищает историю,
  сохраняя состояние RAG.

Принимаются текст, Telegram voice и фото с подписью. Ответ всегда текстовый.
Текст → общий router → RAG/Chroma при RAG ВКЛ либо обычный LLM при RAG ВЫКЛ.
Голос → STT → тот же router; показываются транскрипция и текстовый ответ.
Фото → существующий Vision → текст; с RAG не объединяется.

Состояние RAG хранится как bool в существующем `user_sessions.sessions`
по ключу `<user_id>_rag`. Новая БД не создаётся. Начальное значение определяется
прежним `BOT_MODE`: `rag` включает RAG, остальные значения выключают.
`/start` не сбрасывает выбранное состояние. После перезапуска RAM очищается.

Команды `/help`, `/stats`, `/index`, `/reset` сохранены.
Техническая альтернатива кнопке: `/mode rag` или `/mode off`.
Старые аргументы `text`, `voice`, `vision` принимаются только как RAG ВЫКЛ;
отдельных состояний для типов ввода больше нет.
Обработчики `/voice`, `/voices`, `/image` удалены; автоматическая генерация
картинок отключена. TTS, типы голосов, конфигурация и сервис генерации
изображений оставлены как неиспользуемый legacy-код.

При запуске автоматической индексации нет. Существующая Chroma загружается;
после первой адаптации обязательно выполните `/index`, чтобы убрать старые данные.
Источники в RAG подтверждают только найденные фрагменты; отсутствие ответа
в них не означает отсутствие требования во всём документе.

## Проверки без реальных ключей

```powershell
$env:TELEGRAM_BOT_TOKEN='123456:offline-test-token'
$env:OPENAI_API_KEY='offline-test-key'
.\.venv\Scripts\python -m compileall -q main.py bot.py config.py handlers services rag utils tests
.\.venv\Scripts\python -m pytest tests -q
```

`test_bot.py` в корне обращается к Telegram; запускайте его отдельно только вручную.
Тесты блокируют сеть. Для проверки реальных документов без embeddings:

```powershell
.\.venv\Scripts\python -c "from rag.loader import document_loader; from config import DOCUMENTS_DIR; chunks = document_loader.load_directory(); print(sorted({c.metadata['source'] for c in chunks})); print(len(chunks))"
```

Не запускайте `/index` до настройки ключа и готовности отправить содержимое
документов провайдеру эмбеддингов. RAG-вопросы также используют API.

Проверено при адаптации: синтаксис корректен, 72 теста прошли, 2 пропущены.
Офлайн-инициализация Telegram handlers прошла. Реальные DOCX дали 219 фрагментов:
Кодекс — 196, Порядок — 6, Инструкция РП — 17. Embeddings не создавались.
В тестах хранилище глобального индекса заменено заглушкой; API и внешняя сеть
заблокированы. Два теста исходного примера, зависевшие от LLM, используют
фиксированные ответы; заглушки STT/TTS привязаны к существующему клиенту.

Локальное `.venv` подготовлено на Python 3.9.13. Для установки в этом старом
окружении предварительно потребовалось `python -m pip install greenlet==3.1.1`
(готовая сборка вместо C++ компиляции); это ограничение локальной проверки,
а не новая зависимость приложения. Для новой установки предпочтительны 3.11/3.12.
FFmpeg в текущем PATH не найден; реальное аудио и Telegram проверяются вручную.
